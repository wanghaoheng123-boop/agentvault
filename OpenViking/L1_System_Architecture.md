# L1: System Architecture

## Memory Layers

This workspace utilizes a **Multi-Agent Hybrid Memory Architecture**. All agents MUST respect layer boundaries and the coordination protocol in `MemoryBank/coord/PROTOCOL.md`.

### 1. OpenViking (Hierarchical Rules — Static)
**Location:** `OpenViking/`
**Purpose:** Static documentation, overarching architecture, rigid rules, and identity.
**Action:** Always read `.abstract` first. Then L0 for identity, L1 for architecture, L2 for operational rules.
**Mutability:** Rarely modified. Changes require updating `.abstract` index.

### 2. Memory Bank (Project State — Semi-Volatile)
**Location:** `MemoryBank/`
**Purpose:** Project-level state and multi-agent coordination for cross-device, cross-agent continuity.

| File / Dir | Purpose | Mutability |
|------------|---------|------------|
| `CURRENT.md` | Single-writer volatile pointer (session, next steps, stale TTL) | Orchestrator / `avcoord refresh` |
| `board.md` | Blackboard: owners, threads, live leases summary | Orchestrator / `avcoord refresh` |
| `activeContext.md` | **Derived** compat summary | Regenerated by refresh |
| `sessions/<id>.md` | Create-once handoff detail | Creating agent once |
| `agents/registry.json` | Agent ids, personas, write_scopes | Rare |
| `agents/<id>/context.md` | Private working notes | Owning agent only |
| `coord/` | PROTOCOL, leases, maildir, next_ids, audit | Via `scripts/coord/avcoord.py` |
| `projectbrief.md` | Core mandate | Set once per project |
| `productContext.md` | UX / domain | Set once per project |
| `systemPatterns.md` | Architecture patterns | Per major decision |
| `techContext.md` | Tech stack | Per stack change |
| `progress.md` | **Append-only** ledger (allocate Entry # first) | Append after milestones |

**Action:** Boot reads `CURRENT.md` + `board.md` + PROTOCOL. NEVER delete entries from `progress.md`.

### 3. GraphRAG (Relational Logic Layer)
**Location:** `GraphRAG/`
**Purpose:** Complex dependencies between AI concepts, tools, and workflows.
**Action:** Query when connecting multiple technologies. Add node + edges under lease + atomic write.

### 4. Episodic State Tracker (Time-Series Iteration Memory)
**Location:** `EpisodicTracker/`
**Purpose:** Machine-readable chronological log of learning episodes.
**Preferred write:** append `events.jsonl` with allocated `EP-NNN` (**HOT**).
**WARM:** `avcoord rotate-events --keep 50` → `EpisodicTracker/archive/`.
**COLD:** VectorRAG refs / digests — load on demand only.
**Legacy:** `state_tracker.json` — lease + atomic write only; avoid bulk rewrites.
**Difference from `progress.md`:** Progress is human-readable; Episodic is structured for query.

### 5. Vector RAG (External Reference Layer)
**Location:** `VectorRAG/`
**Purpose:** Heavy unstructured references. Claim-check via paths/IDs in messages.
**Action:** Check `index.json`. Never load bulk into context unless necessary.

## Coordination Runtime

`scripts/coord/avcoord.py` — claim/release/renew, post/recv/ack, next-id, refresh, doctor, test.
Patterns: OACP-style maildir, dibs/lockito TTL leases, pi-ensemble blackboard + audit.
